本机路由部分按落盘流水聚合；路由范围选「全部请求」时会合并外部 Agent 会话的调用轮数与 token （外部会话没有延迟样本时 P50 / 首字显示「—」）。成功率 = 成功尝试 / 全部尝试；P50/P95 是尝试耗时分位数； 首字 P50 是流式请求首个内容块到达时间，缓存读 / 缓存写只算在最后一次成功的尝试上。 熔断阈值连续 3 次失败，冷却 60 秒。 历史流水由旧版本写入、没有首字字段时会显示「—」。 每个上游卡片默认只显示汇总；点「展开模型明细」把这个上游的数据按模型拆开， 逐个模型看调用次数、成功率和耗时，用来分清是整条上游都慢、还是只有某一个模型慢。

界面刷新

两个间隔分开设置，互不影响：请求记录走长连接推送、定时轮询只做兜底；会话对账每次都要重新扫描各家 Agent 的会话文件，节奏可以更慢。默认都是 5 秒。
只影响当前设备 / 浏览器，桌面和手机可以分别设置；会话对账要扫多个会话文件，建议不低于 5 秒。

首字与耗时口径

三家面板对「首字」和「总耗时」的掐表位置不一样，同一个请求会得到三个数。这里选一套口径， 「请求记录」里的首字、总耗时与 TPS 会按它重算（原始会话记录不动，只换算法）。 本机路由流水是转发时实测写入的，健康看板按那份原始数据统计，不参与换算。
口径首字怎么算耗时怎么算已知偏差
happycoding
New API		 第一个 SSE data: 帧到达（含 role 空帧 / block-start 这类不带内容的帧），从网关开始处理请求算起 网关开始处理 → 响应写回完成，截断到整秒（Unix() 秒差） 起点在读完请求体、选完渠道之后，前面的排队与上传不计入，所以数字最小
magpie
本地网关 3425		 上游第一个有内容的字节（跳过空帧），网关从收到请求头开始算，含把请求体传给上游的时间 首字 + 纯解码段，到最后一个字节，毫秒精度 会话记录里没有「网关收包」时刻：按会话 + 输入/输出/缓存读 token去 Magpie 用量日志对账，对上直接取它的 ttft_ms / ms（实测误差 0 ms）；对不上的回退到 DSH request/header 时刻，再没有就退回 step 口径
dsh
会话记录		 第一个流帧到达，从 step/start 算起 step/start → assistant/message 落盘，毫秒精度 含 DSH 自己序列化请求体的时间（实测中位 +1.8 秒），所以数字最大
三套口径都从 DSH 会话里的同一批时间戳换算，原始记录不改： happycoding = 首帧 + 整秒截断；magpie = Magpie 网关实测（对不上时用 request/header 时刻推算）；dsh = 首帧 + 到消息落盘。 起点都是 step/start；magpie 口径会读 GET /v1/magpie/usage/requests（本机没开 Magpie 时自动回退）， 请求页右上角会显示「网关实测 N / M 轮」，展开单条请求还能看到这条记录用的是哪套时间。

上游网络出口

有的上游直连更快，有的必须走代理才快。这里配好本地端口，再到每个上游的「编辑」里选它走哪条。
关键：Clash 开 TUN 时，程序「不设代理」并不等于直连 —— TUN 在网络层把 TCP 全接走了， 走哪儿由 Clash 规则决定，所以规则模式一开，全部上游都过代理。 要让「直连」真直连，就得让 Clash 开一个 proxy: DIRECT 的端口（下面片段直接抄）。
不想改 Clash 配置：把 Verge 的 TUN 关掉、只用它的端口（系统代理开不开都行）—— 本程序是显式连端口出网的，规则模式照旧生效，直连模式也就成了真直连，两边都不用改配置。
